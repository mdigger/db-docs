# PostgreSQL Schema Documentation Generator

Мощная и гибкая утилита на языке **Go** для автоматической генерации красивой и структурированной документации по базам данных **PostgreSQL**. Инструмент сканирует структуру базы данных (таблицы, представления, функции, триггеры, комментарии и т.д.), группирует объекты по схемам и логическим подразделам на основе гибкого конфигурационного файла (`config.json`) и экспортирует результат в удобный формат (например, HTML или Markdown).

---

## Основные возможности

* **Автоматический интроспектинг БД:** Подключение к PostgreSQL и извлечение метаданных объектов (схем, таблиц, колонок, типов, комментариев, функций).
* **Гибкая система группировки (Sections):** Возможность делить объекты внутри схем на логические подразделы (например, «Справочники», «Журналы», «Бизнес-логика») или выводить их единым списком.
* **Правила сопоставления объектов (Matching Rules):**
  * По точному совпадению имени (`exact`).
  * По префиксу (`prefixes`).
  * По вхождению подстроки (`contains`).
* **Кастомные секции по умолчанию («Прочее»):** Автоматический сбор всех объектов, не попавших ни под одно правило, в специальный раздел.
* **Поддержка комментариев БД:** Извлечение описаний (комментариев) как для самих схем, так и для таблиц/колонок/функций, созданных с помощью `COMMENT ON ...`.
* **Настройка через JSON:** Полностью декларативный конфиг для управления заголовками, подвалами, списком схем и правилами классификации.

## Структура и возможности конфигурационного файла (`config.json`)

Конфигурационный файл управляет тем, какие схемы обрабатывать, как называть разделы документации и какие объекты в них помещать.

### Полный пример `config.json`

```json
{
  "header": "Документация корпоративной базы данных v2.4",
  "footer": "Автоматически сгенерировано утилитой генерации документации PostgreSQL. Конфиденциально.",
  "default_section": "Прочие объекты",
  "default_section_desc": "Объекты базы данных, не вошедшие в основные логические модули.",
  "schemas": [
    {
      "name": "public",
      "sections": [
        {
          "name": "Пользователи и роли",
          "description": "Таблицы и представления, отвечающие за учетные записи и авторизацию.",
          "exact": ["users", "roles", "user_roles"],
          "prefixes": ["usr_", "auth_"],
          "contains": ["profile"]
        },
        {
          "name": "Справочники",
          "description": "НСИ (нормативно-справочная информация), статусы и классификаторы.",
          "prefixes": ["ref_", "dic_"],
          "contains": ["dictionary", "status"]
        }
      ]
    },
    {
      "name": "admin",
      "sections": [
        {
          "name": "Журналирование и аудит",
          "description": "Системные логи и аудит безопасности.",
          "prefixes": ["audit_", "log_"]
        }
      ]
    },
    {
      "name": "state",
      "sections": []
    }
  ]
}
```

---

### Подробное описание полей конфигурации

| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `header` | `string` | Текст заголовка, отображаемый в верхней части итогового документа. |
| `footer` | `string` | Текст подвала (футера) документа. |
| `default_section` | `string` | Название раздела по умолчанию (например, `"Прочие объекты"`), куда попадают нераспределенные объекты схемы. |
| `default_section_desc` | `string` | Описание (подзаголовок) для раздела по умолчанию. |
| `schemas` | `array` | Список схем базы данных для документирования. |

#### Свойства элемента массива `schemas`:
* `name` (string) — Имя схемы в базе данных (например, `public`, `admin`).
* `sections` (array) — Массив логических подразделов для фильтрации объектов внутри данной схемы.
  * *Важно:* Если массив `sections` **не указан** или пуст (`[]`), то все объекты схемы выводятся единым списком **без** разделения на подразделы и без заголовка «Прочее» (идеально для служебных схем `state`, `log`).

#### Свойства элемента массива `sections` (Правила фильтрации):
Объект попадает в подраздел, если его имя удовлетворяет хотя бы одному из трех условий:
1. `exact` (массив строк) — Точное совпадение имени объекта с указанным значением.
2. `prefixes` (массив строк) — Имя объекта начинается с указанного префикса.
3. `contains` (массив строк) — Имя объекта содержит указанную подстроку.

> **Порядок обработки правил:** Объекты распределяются по правилам сверху вниз. Если объект уже был учтен в предыдущем разделе, в последующие подразделы (и в «Прочее») он не попадает.

## Установка и запуск

1. Клонируйте репозиторий и перейдите в папку проекта:
   ```bash
   git clone https://github.com/mdigger/db-docs
   cd db-docs
   ```

2. Убедитесь, что у вас установлен Go (версии 1.18 или выше).

3. Настройте файл подключения к базе данных (через переменные окружения или флаги запуска, например):
   ```bash
   export DB_HOST=localhost
   export DB_PORT=5432
   export DB_USER=postgres
   export DB_PASSWORD=secret
   export DB_NAME=my_database
   ```

4. Отредактируйте `config.json` под структуру вашей базы данных.

5. Запустите приложение:
   ```shell
   go run main.go
   ```
